# PBD Cloth：最终设计方向

## 项目定位

在 Unreal Engine 5.8.1 中从零实现一套可复用的 PBD/XPBD 布料系统。先完成 CPU C++ 后端，再以相同的数据语义和求解阶段实现 Compute Shader 后端。当前 `APbdClothActor` 只作为教学和调试载体，最终形态应是可以挂接到角色上的即插即用组件。

## 最终能力

### 双模拟后端

- CPU：C++ 实现，用于学习、验证、调试和参考结果。
- GPU：Compute Shader 实现，用于并行求解和实际性能目标。
- 两个后端保持相同的粒子、拓扑、约束和时间步语义，但允许采用不同的数据布局与并行算法。

### 外力

- 重力。
- 风力；最终应基于三角形面积、法线和相对空气速度计算，而不只是统一方向加速度。

### 内部约束

- 距离约束，用于抵抗拉伸和剪切。
- 弯曲约束；先实现教学版，再实现基于相邻三角形二面角的正式版本。
- 最终支持 XPBD Compliance，使刚度对时间步和迭代次数更稳定。

### 碰撞约束

- Sphere。
- Box/OBB。
- Capsule。
- 角色模式下从 Physics Asset 获取碰撞体，并根据对应骨骼逐帧更新变换。

### 动态附着约束

- 固定粒子不是永久固定在世界位置，而是运动学粒子：`InvMass = 0` 表示不受普通求解推动，其目标位置仍可随时间变化。
- 支持绑定到 Component Transform、Bone、Socket 或蒙皮表面。
- 硬附着直接满足动态目标位置；柔性附着通过 XPBD Compliance 允许有限偏移。
- 每个子时间步更新目标位置和目标速度，保证角色运动能够正确传递给布料。

### 任意服装网格接入

- 输入静态或骨骼服装网格，提取静止位置、三角形和边邻接关系。
- 从网格边生成距离约束，从共享边两侧三角形生成弯曲约束。
- Skeletal Mesh 可使用骨骼权重或动画蒙皮结果生成附着目标。
- Static Mesh 缺少骨骼信息，必须经过一次绑定/配置，将顶点关联到骨骼、Socket 或身体表面。
- 最终组件应能够挂在角色上，让服装随角色整体移动、骨骼动画和碰撞体运动。

## 核心数据

- Particles。
- Triangles。
- Distance Constraints。
- Bending Constraints。
- Attachment Constraints。
- Sphere、Box、Capsule Colliders。
- CPU 与 GPU 各自的运行时 Buffer。

不同约束类型使用独立数组和独立求解阶段，不采用依赖虚函数的统一约束基类，以便直接映射到 GPU Buffer 和 Compute Dispatch。

## 每个固定子时间步

1. 更新组件、骨骼、Socket、蒙皮表面等附着目标。
2. 更新跟随骨骼的碰撞体。
3. 累积重力与三角形风力。
4. 积分并生成预测位置。
5. 迭代求解距离、弯曲、碰撞和附着约束。
6. 根据最终位置更新速度。
7. 将模拟位置提交给显示网格。

## 实施路线

1. 调试显示规则粒子网格、结构边和三角形。
2. CPU 固定时间步、重力、距离约束与动态附着目标。
3. CPU 风力、弯曲约束和 Sphere/Box/Capsule 碰撞。
4. XPBD、子步、稳定性和 CPU Jacobi/并行友好版本。
5. 从任意网格生成拓扑和约束。
6. 封装 `UPBDClothComponent`，接入角色骨骼、Socket 和 Physics Asset。
7. 建立 GPU Buffer、RDG/Compute Shader 调度并逐阶段迁移。
8. GPU 直接驱动布料顶点显示，避免每帧 GPU→CPU 回读。

## 验收原则

距离约束网格只是第一阶段验证，不是项目终点。最终成果必须同时具备多约束、动态角色附着、角色碰撞、任意服装网格接入以及 CPU/GPU 双后端。
